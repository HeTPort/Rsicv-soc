## Problem found by the first clean run

The first `-RegenerateAct4` attempt passed every local gate but failed before
ACT4 generation. `run_release_verification.ps1` constructed
`@("-Jobs", $Act4Jobs)` and splatted that array after explicit `-Extension I`.
For a PowerShell script call, the array elements were positional arguments, so
the literal string `-Jobs` was bound as the integer `Jobs` value.

Named hashtable splatting was selected over manual positional ordering because
it preserves the meaning of `Jobs`, `Act4Root`, `Act4WorkDir`, and `WslRepoPath`
independently of parameter order. The corrected snapshot was recreated from
scratch and the complete command was rerun.

## Command

From `sim/regress/` in the detached worktree:

.\run_release_verification.ps1 -RegenerateAct4 -Act4Jobs 8
